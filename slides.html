Introduction

GRTeclyn

  • GRTeclyn has been in development for several years now and is now at a point where it can be used in production 🎉
  • Documentation: https://grtlcollaboration.github.io/GRTeclyn

Things that work

  • Adaptive mesh refinement
  • NVIDIA/AMD/Intel GPU offloading
  • CCZ4 evolution + Moving puncture gauge
  • Binary black hole example with/without TwoPunctures initial data
  • Puncture tracking
  • Scalar field (Oscillaton) example
  • Derived quantities (e.g. \(\Psi_4\), Constraint violations, EM Tensor)
  • Particle-based AMR interpolator
  • GW Extraction

In development/planned/this hackathon

  • Reductions (e.g. \(L^2\) norms of constraints)
  • Compatibility with GRTresna (IC solver)
  • Apparent Horizon finder
  • Modified Cartoon formalism support
  • ADM mass and momenta computation
  • Other examples

Purpose and aims

  • This hackathon is intended to be informal and collaborative.
  • There is no pressure or expectation to produce a completely polished new feature for the GRTeclyn by the end.
  • Our main aim is to have more people using and familiar with GRTeclyn.
  • We’d also like to hear any feedback you have on the code and documentation.
  • Our secondary goal is to kick-start the process of moving users from GRChombo to GRTeclyn.

Running GRTeclyn on Zenith

Logging on with a training account

  • If you didn’t opt out, you should receive an email with your training account username and a one-time link to collect the password.

  • Please store the password somewhere safe (e.g a password manager) or write it down and keep it safe.

  • MFA has been disabled on your training account so you should be able to log in with just your username and password.

  • SSH to the following login node with your training account username:

    ssh zXXX@login-dawn.hpc.cam.ac.uk

    Note that these login nodes have a different CPU microarchitecture to the Zenith compute nodes.

  • Usual courtesies on the login nodes apply e.g. don’t run long jobs.

Building the BinaryBH example for Zenith

  1. Clone the AMReX repository into e.g. your home directory:

    git clone https://github.com/AMReX-Codes/amrex.git

  2. Clone the GRTeclyn repository under the same parent directory e.g. also in your home directory:

    git clone https://github.com/GRTLCollaboration/GRTeclyn.git

  3. Load the following modules:

    module purge
module load rhel9/mi355x/base
module load openmpi/5.0.10/llvm-amdgpu-7.14/pu3qyle7 # maybe tab-complete this one

  4. Create a file at ~/amrex/Tools/GNUMake/Make.local-pre with the following contents:

    USE_HIP = TRUE
AMREX_AMD_ARCH = gfx950

  5. Navigate to the BinaryBH example and run make:

    cd ~/GRTeclyn/Examples/BinaryBH
make -j 4

Submitting jobs

  • You can submit jobs using a SLURM submission script. An example is provided in the GRTeclyn documentation.

  • You can also start an interactive shell on the login nodes:

    module purge
module load rhel9/mi355x/base
sint -N1 -n1 -c16 --gres=gpu:1 -p mi355x --qos=INTR --time=00:10:00 --account=ZEA-P004-ZENITH-GPU

  • You will need to ensure you specify:

    • --partition=mi355x for the Zenith GPU partition
    • --account=ZEA-P004-ZENITH-GPU for our GRTeclyn allocation

  • The SLURM reservation is magnetic so you shouldn’t need to specify it.

  • We only have 2 nodes (16 GPUs) reserved for the hackathon so please be considerate:

    • Build on the login node and only submit jobs to run on the compute nodes.
    • Keep test jobs short (≤ 10 minutes) and small (1 GPU). Each GPU has 288GB of VRAM so can fit a production-sized Binary BH simulation.
    • Only submit 1 job at a time.
    • Please ask if you need more time or resources for a particular job.

Contributing to GRTeclyn

Repository access

  • For security reasons, write access to the GRTeclyn repository is restricted.

  • If you would like to contribute some code, please fork the repository and submit a pull request from the fork.

  • If you think you will become a regular contributor, we can provide you with write access to the repository so please ask.

  • You can also fork the repository if you intend to work on your own examples/capabilities that you don’t want to add to the main repository.

  • You can add multiple remote repositories to your local clone using the command:

    git remote add <remote name> <remote URL>

Step-by-step guide

  1. Start on the main branch that is up-to-date with the main repository.

  2. Create a new branch for your new contribution:

    git switch -c enhancement/my_new_contribution

  3. Work on this new branch and commit your changes regularly.

    • Make sure the tests pass and you can run an example with your change (if applicable).
    • Please update the documentation in the docs folder accordingly.

  4. Push your branch to your forked repository or the main repository if you have write access:

    git push -u <remote name> enhancement/my_new_contribution

  5. Open a pull request from your branch to the main branch of the main repository with a clear description of your changes.

Code conventions

  • More details in the docs: https://grtlcollaboration.github.io/GRTeclyn/coding_conventions/

  • Please ensure your code is formatted with clang-format. You can make sure this is done when you commit by setting up pre-commit:

    python3 -m pip install --user pre-commit
cd /path/to/GRTeclyn
pre-commit install

  • Variable names should be underscored lower case e.g. my_new_variable

  • Function names should start with a verb and be underscored lower case e.g. compute_new_variable().

  • Class names should be CamelCase e.g. MyNewClass. and member variables should be prefixed with m_ e.g. m_my_member_variable.

  • We generally avoid abbreviations in variable and function names with a few exceptions which are listed in the documentation.

  • Follow this style guide for commit messages:

    • Imperative mood in subject line ideally < 50 chars. Capital letter at start, no full stop at the end.
    • Body containing what and why you have done, wrapped at 72 chars per line.

  • Rebase your commits to avoid lots of tiny ones.
